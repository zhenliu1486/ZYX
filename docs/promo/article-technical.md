# 我做了一个开源的 Agent Skill 调度台：把任务一次分流到正确的 Skill

> 仓库：https://github.com/zhenliu1486/ZYX ｜ 协议 MIT ｜ 安装：`npx skills add zhenliu1486/ZYX`

## 标题备选

1. 装了一堆 Agent Skill 却老是派错活？我写了个开源调度台 ZYX

3. 从拆书、行业提炼到短剧分镜：我把六类内容请求收进一个 Skill 调度台

## 痛点：Skill 多了，缺的是「路由」这一层

用过 Agent Skill 的人大概都遇到过这种情况：本地装了不少技能，但 Agent 要么想不起来用，要么把一件事派给了不对的能力——把「拆一本书」当成「聊这个作者」，把「写短剧剧本」塞进了通用编码助手。

问题不在单个 Skill 写得好不好，而在中间缺一层**判断和分流**：先搞清楚用户到底要哪一类东西，再交给对应的执行能力，最后把产物按统一规范收回来。

ZYX 就是补这一层的。它是一个兼容开放 Agent Skills 规范（agentskills.io）的路由调度型 Skill，自己不写方法论，只做三件事：**判类型、转委派、收口产物**。

## ZYX 是怎么分层的

整体是三层软融合：

- **第 1 层 · 路由壳（zyx）**：入口薄壳，读用户原话和已有事实，按信号把任务归入六类之一，解析目标能力的本机路径，转发委派。
- **第 2 层 · 执行能力**：独立蒸馏器、dbs 家族、影视聚合层和各子技能，各自维护、各自追上游更新；ZYX 只引用路径，不复制它们的内部文件。
- **第 3 层 · 共享底座（shared）**：增量认知校验、三重交叉验证、质检审计清单、来源可信度分级、产物目录规范、Darwin 式压测口径，抽出来只维护一份，各方引用。

## 六条路由：六类请求，各归各位

| 路由 | 原料类型 | 交给谁 | 产出 |
|---|---|---|---|
| R1 | 一个人（思维方式 / 名人 OS） | 女娲 nuwa-skill | 人物视角 Skill |
| R2 | 一个细分行业 | 大师 master-skill | 行业 Master Skill |
| R3 | 长内容（书/长视频/播客/课程/访谈） | 仓颉 cangjie-skill | 原子能力卡 + Skill 包 |
| R4 | 当下问题（诊断/文案/决策/协作） | dbs 家族 | 报告 / 成稿 / 决策记录 |
| R5 | 影视/短剧/漫剧生产 | video-studio 聚合层 | 剧本 / 设定 / 分镜 / 参数 / 流程 |
| R6 | 已有产物二次迭代 | f2r-feedback-iteration | 迭代产物 + 反馈规则记录 |

R5 聚合层内部还接了七个子技能：剧本开发、竖屏短剧编剧、人物设定库、场景库、动作打斗分镜、微表情参数、全流程生产 SOP。信号冲突时有裁决规则；判断不清时先反问一句，不猜着分流。

## 工程上做了哪些收口

路由只是入口，真正能复用靠的是工程闭环：

- **声明式依赖清单** `deps/manifest.json`：每个依赖叫什么、从哪来、怎么装、必需还是可选、归属哪个父技能，都登记在一份清单里；自检、更新器、安装器共用这一份事实源，不在脚本里硬编码。
- **一键安装器** `scripts/install.sh`：自动识别宿主 skills 目录，复制内置 Skill，可选同时安装外部上游依赖，装完跑自检。
- **自检与完整性**：`doctor.sh` 检查运行依赖、依赖安装状态、文件完整性和悬空引用；`check-integrity.py` 扫描 Markdown 引用的本地文件是否存在。
- **更新闭环**：后台周检对 git 上游做快进更新，有手改或分叉不强行覆盖；自身版本比对同时看版本号和 HEAD SHA；失败计数到阈值才提示人工介入。
- **回归用例**：覆盖路由裁决，以及依赖缺失降级、版本落后/超前、产物命名与脱敏、模糊信号裁决等场景。
- **产物规范**：产物按来源名分目录落盘，统一命名与日期后缀；发布前强制脱敏，敏感信息用占位符替代。

## 安装

```bash
# 方式一：克隆仓库安装
git clone https://github.com/zhenliu1486/ZYX.git
cd ZYX
bash scripts/install.sh
# 可选：同时安装外部上游蒸馏器
bash scripts/install.sh --install-deps

# 方式二：skills CLI
npx skills add zhenliu1486/ZYX
```

兼容 Claude Code、Codex、OpenClaw、Cursor、Gemini CLI、OpenCode 等兼容 Agent Skills 标准的宿主。脚本依赖 Bash / git / curl；仓颉本体另需 Python 3.10+ 与 PyYAML。

## 适合用在什么场景

- 想把某个人的决策方式、思维习惯提炼成可复用的视角 Skill；
- 要把一个细分行业的打法、工具地图、工作流整理成行业 Master Skill；
- 把一本书、一期长视频、一门课程提炼成可复用的方法包；
- 当下生意/文案/决策问题需要先诊断再动手；
- 从点子到成片的短剧、漫剧、动作分镜、人物表情参数这条生产链路；
- 已有产物按反馈反复迭代，把人的判断沉淀成可判定规则。

## 边界先说清楚

ZYX 不自己调研、不提炼方法论、不改写蒸馏器内部文件；R1–R4 上游蒸馏器和可选达尔文压测底座是外部依赖，按清单单独安装；远端写动作（建仓、推送、发 Release）需要明确授权，产物默认只落本机，不自动外发。
