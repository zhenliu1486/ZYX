# zyx 路由回归用例（evals）

> 用途：改动路由表 / 入口脚本后，逐条核对「输入 → 应路由到的 Skill」是否仍正确。
> 判定方式：每条用例给出用户原话、预期路由代号、预期子技能（若有）、不应误判的方向。
> 压测口径见 `../shared/darwin/pressure-test.md`；本目录只做路由裁决回归，不跑产物质量压测。

## 用例清单

| # | 类型 | 用户原话（示例） | 预期路由 | 预期子技能 / 衔接 | 防误判 |
|---|---|---|---|---|---|
| E1 | 人（R1） | 「帮我把查理·芒格的思维方式蒸馏成一个可复用的人物视角 Skill，以后遇到决策先按他的视角想一遍。」 | R1 女娲 nuwa-skill | 人物视角 Skill；增量先验 + 三重验证 | 不按行业打法走 R2；不按拆书走 R3 |
| E2 | 行业（R2） | 「我想做跨境电商这行，帮我把这行的大佬打法、工具地图、工作流和信息源整理成一个行业 Master Skill。」 | R2 大师 master-skill | Phase3 生成 top3 人物 sub-skill 时委派 R1 女娲 | 不按单个人物走 R1；不按当下问题走 R4 |
| E3 | 长内容（R3） | 「这是《穷查理宝典》的摘录，帮我提炼成可复用的方法包，压测通过后入库。」 | R3 仓颉 cangjie-skill | 无文字稿时先走 dbs-video-extract / 本地转写；阶段4 兼容达尔文压测 | 不按人物视角走 R1；不按当下生意诊断走 R4 |
| E4 | 当下问题（R4） | 「我这门小生意现在获客成本越来越高，帮我诊断一下问题出在哪、先改哪一步。」 | R4 dbs 主调度台 | dbs 内部再分发到具体子 skill | 不沉淀成可安装 Skill；不走 R1/R2/R3 |
| E5 | 内容生产（R5） | 「帮我构思一个竖屏复仇短剧的开头三集，人物和场景先定下来，再出打斗戏分镜。」 | R5 video-studio 聚合入口 | 内部路由：short-drama-screenwriter（剧本）→ manju-character-library / manju-scene-library（设定）→ cinematic-fight-direction（动作分镜） | 不走拆书 R3；不按电商带货编导处理 |
| E6 | 产物迭代（R6） | 「这是上一版编导脚本，按我这几条反馈再改一版，把没打中我的地方改掉。」 | R6 f2r-feedback-iteration | 负反馈显性化为规则、小样本迭代 + 回归；必要时联动 dbs-resonate / dbs-ai-check | 不从零重新蒸馏；不走 R5 全新生产 |

## 回归执行

1. 逐条把「用户原话」喂给 zyx 入口，记录实际路由代号。
2. 与「预期路由」比对；不一致即视为回归失败，先查 routing-table.md 信号定义，再查 route.sh 解析。
3. 新增原料类型时，先在本表补一条用例，再改路由表。
