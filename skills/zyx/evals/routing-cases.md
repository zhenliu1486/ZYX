# zyx 路由回归用例（evals）

> 用途：改动路由表 / 入口脚本后，逐条核对「输入 → 应路由到的 Skill」是否仍正确。
> 判定方式：每条用例给出用户原话、预期路由代号、预期子技能（若有）、不应误判的方向。
> 压测口径见 `../shared/darwin/pressure-test.md`；本目录只做路由裁决回归，不跑产物质量压测。

## 用例清单

| # | 类型 | 用户原话（示例） | 预期路由 | 预期子技能 / 衔接 | 防误判 |
|---|---|---|---|---|---|
| E1 | 人（R1） | 「帮我把查理·芒格的思维方式蒸馏成一个可复用的人物视角 Skill，以后遇到决策先按他的视角想一遍。」 | R1 女娲 nuwa-skill | 人物视角 Skill；增量先验 + 三重验证 | 不按行业打法走 R2；不按拆书走 R3 |
| E2 | 行业（R2） | 「我想做跨境电商这行，帮我把这行的大佬打法、工具地图、工作流和信息源整理成一个行业 Master Skill。」 | R2 大师 master-skill | Phase3 生成 top3 人物 sub-skill 时委派 R1 女娲 | 不按单个人物走 R1；不按当下问题走 R4 |
| E3 | 长内容（R3） | 「这是《穷查理宝典》的摘录，帮我提炼成可复用的方法包，压测通过后入库。」 | R3 仓颉 cangjie-skill | 无文字稿时先走 dbs-video-extract / 本地转写；阶段4 兼容达尔文压测 | 不按人物视角走 R1；不按当下生意诊断走 R4 |
| E4 | 当下问题（R4） | 「我这门小生意现在获客成本越来越高，帮我诊断一下问题出在哪、先改哪一步。」 | R4 dbs 主调度台 | dbs 内部再分发到具体子 skill | 不沉淀成可安装 Skill；不走 R1/R2/R3 |
| E5 | 内容生产（R5） | 「帮我构思一个竖屏复仇短剧的开头三集，人物和场景先定下来，再出打斗戏分镜。」 | R5 video-studio 聚合入口 | 内部路由：short-drama-screenwriter（剧本）→ manju-character-library / manju-scene-library（设定）→ cinematic-fight-direction（动作分镜） | 不走拆书 R3；不按电商带货编导处理 |
| E6 | 产物迭代（R6） | 「这是上一版编导脚本，按我这几条反馈再改一版，把没打中我的地方改掉。」 | R6 f2r-feedback-iteration | 负反馈显性化为规则、小样本迭代 + 回归；必要时联动 dbs-resonate / dbs-ai-check | 不从零重新蒸馏；不走 R5 全新生产 |
| E11 | 知识库（R7） | 「帮我建一个关于 AI 基础设施的知识库，以后我看到文章就往里加，能随时问库里的结论。」 | R7 wiki-vault | `wiki.py init` 建 raw/ 与 wiki/；后续 ingest 编译、query 库内问答、lint 巡检 | 不按一次性拆书包走 R3；不按人物/行业深蒸馏走 R1/R2 |
| E12 | 知识库（R7） | 「我 Obsidian 里已经有个读书笔记库，直接接进去用，别动我的目录。」 | R7 wiki-vault | `wiki.py mount <slug> <路径>` 只登记、不重构；缺结构默认不写，用户同意后才 `--provision` | 不搬动/改名/重排用户既有目录；不擅自创建 raw/wiki |
| E13 | 知识库并发（R7） | 手上有两个会话都要往同一个库写页面 | 必须写同一活动库、串行执行 | 先 `lock` 再写、写完 `unlock`；未持锁写入被拒（退出码 5）；他会话持锁则拒（退出码 3），陈旧锁才 `--force` | 不并行写同一库；不跳过锁硬写 |

## 非路由类回归用例（降级 / 版本 / 规范）

| # | 类别 | 场景 | 预期行为 | 不应出现 |
|---|---|---|---|---|
| E7 | 依赖缺失降级 | 目标蒸馏器/子技能在本机未安装（如干净宿主上 R1 女娲缺失） | route.sh / doctor 明确报「未检测到 <目录>」并给安装命令；必需缺失记 ❌，可选缺失记 ⚠；不臆造安装路径、不假装产出产物 | 不凭空假设路径；不跳过依赖直接出方法论产物 |
| E8 | 版本比对 behind/ahead | 本地版本号/HEAD 落后远端；本地超前远端；远端不可达 | behind 提示人工确认更新（不自动覆盖）；ahead 标注本地未发布；不可达记失败计数、降级继续不中断 | 不自动快进覆盖运行中的 Skill；不因远端不可达中断主流程 |
| E9 | 产物命名与脱敏 | 产物落盘；素材含手机号/身份证/未公开客户名 | 目录用合法 slug + 可选 `YYYYMMDD` 日期后缀；敏感信息替换为占位符（`<手机号>`、`<客户A>`）；未脱敏不进可外发产物包 | 不用 agent id/会话 id/临时文件名命名；敏感原文进 `sources/` |
| E10 | 模糊信号裁决 | 「像人又像行业」「像生产又像蒸馏」等冲突信号 | 先按 routing-table 裁决规则判断；仍模糊时先反问一句确认诉求再分流 | 不猜着分流；不把边界外任务硬塞进某一类 |
| E14 | 知识库巡检（R7） | 库里页面少、覆盖度低，用户仍要基于现有内容下判断 | lint 只输出客观统计与建议（断链/缺页/孤儿/索引覆盖/陈旧/矛盾），由用户自行决定是否可用 | 不设覆盖度闸门、不输出「覆盖不足禁止下结论」、不用非零退出码阻断 |
| E15 | 知识库检索与归档（R7） | 「我库里关于 X 都写过什么？顺便把刚才这段分析归档。」 | R7 wiki-vault | `search` 定位命中页 → 带 wikilink 作答 → `archive` 建对比/综述页 + `--link-from` 回链 + 写 `log query` | 不把答案只留在对话里；不新建脱离图谱的孤页 |
| E16 | 晋级自查（R7） | 「这页内容能不能打包成一个 Skill？」 | R7 wiki-vault → R3 | 先 `promote-check` 只读自查（来源/可信度/关联/可执行/边界），再按三重验证 + 独立复用价值决定是否交 R3 | 不把自查当成自动晋级闸门；不跳过 R3 评估直接产出 Skill 包 |

| E17 | 豆包会话开场（R7） | 「在豆包个人助理里打开我的知识库，先说说库里有什么。」 | R7 wiki-vault | 先 `where` 确认库，再 `brief` 输出 ≤600 字（规模/最近/热缓存/缺口）；按需 `--with-lint` | 不整库塞上下文；不凭记忆编造库内页名 |
| E18 | 豆包环境建库（R7） | 「在豆包这边给我建个关于城市漫步的库。」 | R7 wiki-vault | 豆包环境默认落 `~/Doubao/wiki/<slug>`（`ZYX_WIKI_HOME` 可覆盖）；建完用 `where` 回传位置 | 不落到临时目录/会话目录；不假设桌面路径存在 |

| E19 | 视觉产物验收（Look Gate） | 「这版 PPT/封面/分镜直接发我。」 | 交付前先 `look.py` 渲染，agent 亲自 Read `look.png`，修溢出/对比度/层级/手机可读性/缺字；未看不得宣称已验证 | 不把源文件当“已验收”；不做纯文本 QA 代替视觉验收 |
| E20 | 跨宿主 Context 卡（R7） | 「换到另一个 agent，它怎么知道我的库？」 | `wiki.py context --install` 生成 `zyx-context` 卡，装到 `~/.agents/skills` 与已存在宿主；`use` 换库自动刷新；只覆盖 managed 卡 | 不覆盖用户同名技能；不把整库内容塞进技能卡；不改 `~/.agents/AGENTS.md` |
| E21 | Omarchy 握手（环境层） | 「帮我把 Omarchy 桌面调一下。」 | 握手后交给 Omarchy 的 `omarchy` skill；ZYX 只报版本/主题/默认 agent 与安装状态 | 不新增 R8 路由；不改 `/usr/share/omarchy`；不复制 Omarchy 技能 |

## 回归执行

1. 逐条把「用户原话」喂给 zyx 入口，记录实际路由代号。
2. 与「预期路由」比对；不一致即视为回归失败，先查 routing-table.md 信号定义，再查 route.sh 解析。
3. 新增原料类型时，先在本表补一条用例，再改路由表。
