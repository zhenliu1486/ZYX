# Darwin 式压测底座（兼容达尔文 skill）

> **引用方与挂载阶段**：仓颉（R3，阶段 4 压测）、其他蒸馏器产物在交付前可选引用；zyx 回归用例（evals/）共用本口径。挂载阶段：产物入库前的行为验证与回归环节。
>
> 借鉴达尔文（darwin-skill）的核心原则：Skill 好不好，只有装上之后 agent 干同一件活是否真的更好才算数；读文档打分只用来找毛病，保留还是回滚由实跑决定。本目录提供共享压测用例口径，仓颉阶段 4 与其他蒸馏器产物均可引用。

## 1. 核心原则

- **行为验证，不看文档自评**：用真实任务跑带产物与不带产物的两版产出，盲评真实结果，而不是评委读 SKILL.md 投票。
- **棘轮机制**：只保留可测量改善的改动；没有增益或回退的改动回滚。关键阶段保留人工检查点。
- **留出集**：测试用例要包含训练/提炼时没见过的任务，防止只背下原材料。

## 2. 压测用例格式（evals/ 目录）

每个压测用例写成独立文件或统一 `eval-cases.json`：

```yaml
- id: <用例编号>
  task: <给 agent 的真实任务描述>
  input: <素材/上下文路径或内联内容>
  expect: <可观察的预期行为或产出要点>
  rubric:
    - 维度: <如：结论是否可执行 / 边界是否说清 / 是否出现常识废话>
      判据: <可判定标准>
  baseline: <不带产物时的产出记录（可选，用于对比）>
```

## 3. 执行与判定

1. 为每个候选产物准备 ≥3 条用例，其中至少 1 条留出集。
2. 分别在「带产物」与「不带产物」条件下跑同一批任务，记录 transcript 与产出。
3. 盲评两版产出：按 rubric 逐条判断是否更可执行、更准、更贴合任务；绕路、多绕工具调用、遗漏边界都记为问题。
4. 判定：实测有可测量增益 → 保留；无增益或损坏既有能力 → 回滚；存疑 → 进入人工检查点，不自动保留。

## 4. 与达尔文本体的关系

- 达尔文 skill（`alchaincyf/darwin-skill`，v3.0.2）是独立上游项目，作为第 3 层底座被引用；zyx 与各蒸馏器不复制它的脚本与评测协议。
- 需要完整九维 rubric、盲评协议、git 回滚与成果卡片时，调用本机安装的达尔文 skill；本目录只保留最小可用口径，避免重复造轮子。
- 仓颉流水线阶段 4 的压力测试按本目录口径执行，评测协议细节与达尔文保持兼容。

## 5. 证据边界

- 未实跑过的任务不宣称「已验证变好」；压测未覆盖的能力在 MANIFEST 标注「未测」。
- 压测记录随产物归档到 `evals/`，供质检审计追溯。
