# 三重交叉验证

> **引用方与挂载阶段**：女娲（R1，人物单元定稿前）、大师（R2，行业结论定稿前）、仓颉（R3，编译产物入库前）；zyx 收口时复核。挂载阶段：候选方法论单元进入产物前的校验闸门。
>
> 候选方法论单元在进入产物前，必须依次过三道闸门。女娲/大师/仓颉共用本口径；各蒸馏器可在自己的流水线里挂到对应阶段，但三道闸门的定义与通过标准保持一致。

## 1. 三道闸门

### 闸门 A · 来源充分性
- 结论是否有一手材料支撑（本人原话、原始案例、原始文档、可核实记录）。
- 是单处出现还是多处互证；只在一处讲透的完整机制也可入选，但要在产物里标明「单源」。
- 二手转述、评论、推测与一手材料分开留痕，不混为一谈。

### 闸门 B · 可执行性
- 这条方法在真实场景下能不能照着做：是否有明确步骤、触发条件、判断依据，而不是一句口号或价值观。
- 能否拆出动作序列（先做什么、再做什么、依据什么判断）；纯概念、纯感悟不进可执行层。

### 闸门 C · 任务增益
- 模型没有这份材料时会不会答不出/答不准/答得浅；用在具体任务上是否比通用建议多出增量。
- 删掉这条，产物是否明显变薄；删掉后无损失的条目淘汰。

## 2. 判定记录

每个候选单元记录：

| 字段 | 取值 |
|---|---|
| 单元标识 | slug |
| 增量类型 | 推翻 / 加深 / 新增（见 `incremental-check.md`） |
| A 来源充分性 | 通过 / 单源 / 不足；附来源编号 |
| B 可执行性 | 通过 / 部分 / 不足 |
| C 任务增益 | 通过 / 不足 |
| 处置 | 入选 / 晋级独立 Skill / 参考待核查 / 淘汰 |

- 三道闸门任一「不足」：不进正文；放入参考待核查区，标注缺哪一项。
- 通过 A、B、C 且具备独立复用价值：可晋级为独立入口 Skill；否则作为路由包内的能力卡。

## 3. 交叉验证口径

- 同一结论至少对照两类不同来源；来源之间存在矛盾时保留矛盾，标注各方依据，不和稀泥。
- 来源可信度分级见 `../credibility/source-grading.md`。
- 验证结果随产物留痕，供 `../quality/qa-audit.md` 审计追溯。
