# 质检与审计清单

> **引用方与挂载阶段**：女娲（R1）、大师（R2）、仓颉（R3）、dbs（R4）、video-studio（R5）、f2r（R6）产物收口前；zyx 统一收口门。挂载阶段：产物交付/发布前最后一道质检。
>
> 产物交付前的统一质检门，以及全程可追溯的审计痕迹要求。女娲/大师/仓颉/dbs 产物在收口前都按本清单过一遍。

## 1. 交付前质检门（逐条核对）

### 结构与规范
- [ ] `SKILL.md` frontmatter 含 `name`（与目录名一致、小写连字符）、`description`（写明做什么 + 何时用，1–1024 字符）。
- [ ] 正文不超过 500 行；详细参考资料拆到 `references/`，脚本放 `scripts/`，素材放 `assets/`。
- [ ] SKILL.md 引用到的 references/scripts/assets 文件都真实存在；无悬空引用。
- [ ] 目录内无个人目录绝对路径、无本机隐藏配置、无密钥/令牌。

### 视觉验收（仅视觉产物：PPT/HTML/PDF/封面/分镜/视频缩略图）
- [ ] 已跑 `../../scripts/look.py`，agent 亲自 `Read` 了 `look.png`；溢出、对比度、层级、手机可读性、一致性、缺字六项通过，或未通过项已记录在 `MANIFEST.md`。
- [ ] 超过 8 页的 PPT/PDF 已用 `--pages` 全量渲染，没有只看前 8 页就宣称通过。
- [ ] 缺渲染工具时，`MANIFEST.md` 明确写“未做视觉验收（缺 X）”，未冒充已验证。

### 内容质量
- [ ] 每条入选结论过三重验证（来源充分性 / 可执行性 / 任务增益），处置留痕。
- [ ] 增量已标注（推翻 / 加深 / 新增），常识废话未占正文。
- [ ] 边界、反例、失效条件已写明；明确标注「不适用什么场景」。
- [ ] 事实、数字、术语可溯源；未核实的判断标为「推断」，不冒充事实。

### 安全与合规
- [ ] 未存全本书 / 完整字幕 / 长段原文，只保留结构化摘要 + 元数据 + 极短引用。
- [ ] **【发布前必过项 · 脱敏】** 个人手机号、身份证、银行卡、住址、内部账号、未公开客户名、未签保密协议的商业数据已全部替换为占位符；`sources/` 内原始素材同样脱敏；含敏感信息的素材不进可外发产物包。
- [ ] 私密样本、聊天记录、内部资料已脱敏；公开前再次确认。
- [ ] 破坏性动作（删除、覆盖、对外发送、远端发布）附近有确认或禁止说明。

## 2. 审计痕迹

每个产物目录保留一份 `MANIFEST.md`（见 `../artifacts/convention.md`），记录：
- 来源蒸馏器名称与版本、生成时间；
- 用过的来源清单（编号 + 可信度分级）；
- 三重验证结果与处置记录；
- 质检门未通过项及处理；压测用例与结果引用；
- 后续若修改，追加修改记录（日期、改动、依据）。

## 3. 交付判据

- 质检门全部通过，或未通过项已在 MANIFEST 里如实标注「未测/待补」，才算可交付；不得把未跑过验证的内容宣称「已验证」。
- **脱敏项未过，禁止发布/外发**；审计记录随产物一起归档；发布到远端前按 `../../references/routing-table.md` 发布段脱敏并单独授权。
